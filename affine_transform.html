01 What is an affine transformation?

An affine transformation is any operation that maps one image (or set of points) to another while preserving parallel lines and ratios of distances along parallel lines. In practical terms: straight lines stay straight, parallel lines stay parallel, but angles and distances can change.

The set of operations captured by an affine transform includes translation (shifting), rotation, scaling, shearing, and reflection. In 2D biomedical imaging this covers the vast majority of registration scenarios — aligning two scans of the same organ, correcting for patient motion, or normalizing cell images to a common coordinate frame.

The key intuition: an affine transform is a linear transform + a translation. Those two pieces combine into one unified matrix using the homogeneous coordinate trick described below.

02 Why a 3×3 matrix for 2D?

At first glance the 3×3 structure looks wasteful — the bottom row is always [0, 0, 1] and seems to do nothing. But it exists to solve a fundamental problem: translation cannot be expressed as a pure matrix multiplication in 2D.

Core problem
A 2×2 matrix times a 2-vector always produces a linear combination of the input coordinates. That means the origin (0,0) always maps to (0,0) — you can never shift the image. Translation requires adding a constant, which is fundamentally non-linear.

The fix is the homogeneous coordinate: every 2D point (x, y) is represented as a 3-vector (x, y, 1) — that appended 1 is the homogeneous coordinate. Now a 3×3 matrix multiply can accomplish translation in the top-right column:

┌ ┐ ┌ ┐ ┌ ┐ │ a b tx │ × │ x │ = │ ax + by + tx │ │ c d ty │ │ y │ │ cx + dy + ty │ │ 0 0 1 │ │ 1 │ │ 1 (always) │ └ ┘ └ ┘ └ ┘

The tx * 1 = tx term is what makes translation "show up" — the appended 1 in the input vector is literally what activates the translation column. The bottom row [0, 0, 1] ensures that the 1 always passes through unchanged, keeping every result in the same homogeneous space.

03 Anatomy of the matrix

The 3×3 affine matrix has three distinct functional zones:

2×2 linear core [ a b / c d ]
Handles rotation, scale, shear, and flip. These are all linear transforms — they preserve the origin. The origin (0,0) always maps to (0,0) through this block alone.
Translation column [ tx / ty ]
Pure shift in X and Y. Completely isolated from the linear part — changing tx/ty never affects rotation or scale. This separation is clean because of the homogeneous coordinate structure.
Homogeneous row [ 0 0 1 ]
Always fixed in 2D affine transforms. Ensures the homogeneous coordinate propagates through unchanged. In projective (homography) transforms, this row takes non-zero values to create perspective distortion.
Input vector [ x / y / 1 ]
Every point gets an appended 1. This is the homogeneous coordinate — without it, the translation column has nothing to multiply against and the shift is lost.
04 Each transform type — what's actually changing
TransformWhat changes in the matrixPhysical intuition
Rotation θ a=cosθ, b=−sinθ, c=sinθ, d=cosθ Rotates about the origin. All four purple cells change in a coordinated way because rotation mixes x and y together — "how much of the old x ends up in the new x/y."
Scale a=sx, d=sy (off-diag = 0) Stretches or compresses each axis independently. Negative scale = flip. sx=−1 mirrors left-right.
Shear X b=shx Slides rows horizontally proportional to their Y position. Like italicizing a rectangle — top slides right, bottom stays, middle moves in between.
Translation tx, ty in right column Pure pixel shift. Completely independent of the 2×2 block. This is the only transform that truly requires the 3×3 structure.
Identity a=d=1, all others=0 No change. Every point maps to itself. The reference point — "doing nothing" is still a valid matrix.
05 Transform composition — the practical payoff

Because everything lives in a single matrix, you can chain transforms by multiplying their matrices together before touching a single pixel. This is the real practical payoff of the homogeneous coordinate trick.

Example
Rotate 30°, then scale by 1.5×, then translate by (50, 20)? Multiply M_rotate × M_scale × M_translate into one matrix M_combined. Apply M_combined to every point once. Same result, far fewer operations — especially critical when processing millions of pixels.

Note that matrix multiplication is not commutative for transforms. Rotate-then-translate is different from translate-then-rotate. The order matters physically: the second matrix is applied first (standard right-to-left convention in most libraries).

In biomedical imaging
This composability is why affine registration pipelines can build up complex multi-step alignments efficiently. OpenCV's warpAffine, PyTorch's affine_grid, and Cellpose's spatial transform internals all rely on this matrix representation. The 3×3 form also generalizes cleanly to 3D: a 4×4 matrix with the same structure handles volumetric image registration.
06 Your summary (verified correct)

After working through the interactive demo, these are the key takeaways — confirmed accurate:

  • The 2×2 purple core handles linear transforms: rotation, scale, shear, and flip. The unifying property is that they all preserve the origin — mathematically they are expressible as pure linear combinations of x and y.
  • The teal translation column captures the constant shift (tx, ty) that a pure 2×2 matrix cannot express.
  • The full 3×3 structure with the homogeneous row is what unifies both into a single matrix multiply — no separate addition step needed.
  • Appending 1 to every input point (x, y, 1) is what "activates" the translation column — tx × 1 = tx delivers the shift.
  • The composability of matrix multiplication is the core practical benefit: chain any sequence of transforms into one matrix, apply once.
