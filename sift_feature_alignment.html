Stage 01
Scale-space & DoG pyramid

The image is blurred repeatedly with a Gaussian kernel at increasing σ values, forming an octave. Each step blurs more — simulating what the image looks like from farther away.

Difference of Gaussians (DoG) is computed by subtracting adjacent blurred images. This approximates the Laplacian of Gaussian (∇²G), a blob detector that responds strongly at edges and blobs at the right scale.

After one octave, the image is downsampled 2× and the process repeats — creating a pyramid of DoG images spanning many scales.

KEY FORMULA
DoG(x,y,σ) = G(x,y,kσ) − G(x,y,σ)

Stage 02
Scale-space extrema detection

Each pixel in a DoG image is compared to its 26 neighbors — 8 in the same scale layer, 9 in the layer above, 9 in the layer below.

A point is a candidate keypoint only if it is a local maximum or minimum across all 26 neighbors. This finds blobs that are distinctive in both space and scale simultaneously.

The resulting candidates are tentative — many will be discarded in the next stage. Only points that survive in both spatial position and across the scale axis are kept.

Stage 03
Keypoint localization & filtering

Two rejection criteria remove unstable candidates:

Low contrast rejection: A Taylor expansion fits a sub-pixel location. If the DoG value at the interpolated peak is below a threshold (~0.03), the point is discarded — it won't be stable under noise.

Edge response rejection: The Hessian matrix at the keypoint describes local curvature. Edge points have one large curvature and one near-zero. The ratio of principal curvatures (like Harris) is checked — if it exceeds a threshold (r = 10), the point lies on an edge and is discarded.

What remains are well-localized, high-contrast, non-edge keypoints.

EDGE REJECTION
(Tr H)² / Det H < (r+1)²/r

Stage 04
Orientation assignment

For each keypoint, gradient magnitudes and orientations are computed in a neighborhood scaled to the keypoint's σ.

These are accumulated into a 36-bin orientation histogram (10° per bin), weighted by gradient magnitude and a Gaussian centered on the keypoint.

The dominant orientation (histogram peak) becomes the keypoint's canonical orientation. Any other peak within 80% of the dominant creates an additional keypoint at the same location — this is how SIFT handles multi-orientation patches.

This step is what makes SIFT rotation-invariant: all subsequent descriptor computation is done relative to this assigned orientation, so rotating the image just rotates the reference frame.

gradient σ 3

Stage 05
SIFT keypoint descriptor

A 16×16 patch around the keypoint (aligned to assigned orientation) is divided into a 4×4 grid of cells. In each cell, gradients are binned into an 8-bin orientation histogram.

This yields 4 × 4 × 8 = 128 values — the SIFT descriptor vector.

The vector is then L2-normalized, clamped at 0.2 (to reduce illumination sensitivity), and re-normalized. This makes the descriptor robust to linear illumination changes.

Matching is done by nearest-neighbor distance ratio: a match is accepted only if the closest descriptor distance is significantly smaller than the second-closest (Lowe's ratio test, threshold ≈ 0.8).

01 Feature-based alignment & intensity vectors

Image alignment can be done two ways. Intensity-based (direct) methods compare raw pixel values across images and optimize a transform to minimize some difference metric — sum of squared differences, normalized cross-correlation, mutual information. These are simple but sensitive to intensity changes, occlusion, and they need a good initialization to avoid local optima.

Feature-based methods first extract a sparse set of salient points from each image, then match those points across images, and finally estimate the transform from the matched correspondences. The key insight is that features can be made invariant to the very changes that break intensity methods.

Intensity vectors
An intensity vector is simply the raw pixel values in a patch around a point, stacked into a vector. It's the naive descriptor. The problem: shift the image by one pixel, rotate it slightly, or change the lighting, and the intensity vector changes completely even though the underlying structure is the same. Good feature descriptors are engineered to avoid this brittleness.

Feature-based alignment has three stages: detection (find the same physical point in both images), description (characterize the patch around each point in a stable way), and matching (pair up descriptors across images). The alignment transform is then estimated from the matched point pairs, typically with RANSAC to reject outlier matches.

In biomedical imaging
Feature-based alignment is used heavily in multi-modal registration (aligning MRI to CT), multi-stain alignment in pathology slides, and stitching tiled microscopy acquisitions. SIFT-derived methods appear in tools like elastix and ANTs for deformable registration pipelines.
02 SIFT overview — what it achieves

Scale-Invariant Feature Transform (SIFT), introduced by Lowe (2004), detects and describes keypoints that are invariant to scale, rotation, and partially to illumination and affine distortion. It is the canonical feature descriptor in classical computer vision.

Scale invariance
Achieved by detecting features in a scale-space pyramid. Each feature carries its own characteristic scale σ, so it is always described at the same relative scale regardless of image resolution.
Rotation invariance
Achieved by assigning a dominant gradient orientation to each keypoint and computing all descriptors relative to that orientation. Rotating the image just rotates the reference frame.
Illumination robustness
Gradient-based descriptors are naturally insensitive to additive illumination changes. L2 normalization + clamping handles multiplicative changes (contrast differences).
128-D descriptor
High-dimensional enough to be distinctive (low false-match rate) but compact enough for efficient nearest-neighbor matching. Lowe's ratio test further reduces false matches.

The full SIFT pipeline has four main stages: build the scale-space DoG pyramid → detect scale-space extrema → localize and filter keypoints → assign orientation and compute descriptor.

03 Scale-space extrema detection

The scale-space of an image L(x, y, σ) is defined as the convolution of the image I with a variable-scale Gaussian G(x, y, σ). Increasing σ progressively blurs the image, simulating viewing from increasing distance and suppressing fine details.

Scale-space: L(x,y,σ) = G(x,y,σ) ★ I(x,y) DoG: D(x,y,σ) = L(x,y,kσ) − L(x,y,σ) Approx: D(x,y,σ) ≈ (k−1)σ² ∇²G ★ I

The Difference of Gaussians (DoG) is a computationally efficient approximation of the scale-normalized Laplacian of Gaussian (LoG). The LoG is a theoretically optimal blob detector — the DoG gives the same scale-space extrema for much less computation since the blurred images are already computed.

Within each octave, s+3 blurred images are generated (where s is the number of scales per octave), producing s+2 DoG images. After one full octave, the image is downsampled by 2× using the already-blurred image at 2σ, and the process repeats. This multi-octave structure spans a large range of scales efficiently.

Extrema are found by checking each pixel against its 26 neighbors (8 in-plane + 9 above + 9 below in scale). A point is a candidate keypoint if it is strictly greater or less than all 26 neighbors.

Why DoG instead of LoG?
The LoG requires a separate convolution at each scale. DoG reuses the already-computed Gaussian-blurred images — the blurred images are a byproduct of the pyramid construction, so subtraction costs almost nothing. At typical values of k ≈ √2, the DoG approximates the LoG within a small constant factor.
04 Keypoint localization & filtering

The initial extrema are coarse — sampled at integer pixel positions on a discrete grid. Lowe improves this with a 3D quadratic Taylor expansion of the DoG function around each candidate:

D(z) ≈ D + (∂D/∂z)ᵀ z + (1/2) zᵀ (∂²D/∂z²) z optimal offset: ẑ = −(∂²D/∂z²)⁻¹ (∂D/∂z)

If the offset ẑ exceeds 0.5 in any dimension, the extremum lies closer to a neighboring sample point and the candidate is moved there. This iterates until convergence or is discarded after too many steps.

Two rejection tests then run:

Low contrast: The DoG value at the interpolated location is evaluated. If |D(ẑ)| < 0.03, the point is discarded — low-contrast features are unstable under noise.

Edge suppression via Hessian: DoG extrema on edges are poorly localized along the edge direction. The 2×2 Hessian H of the DoG at the keypoint captures principal curvatures. A large ratio of principal curvatures means the point is on an edge. If:

H = [ Dxx Dxy ] [ Dxy Dyy ] (Tr H)² / Det H > (r+1)²/r (r = 10 in original paper)

the keypoint is rejected as an edge point. This is essentially the same curvature ratio used in the Harris corner detector, applied here to the DoG response surface.

Why edges are problematic
On an edge, the DoG has a strong response in one direction (perpendicular to the edge) but is nearly flat along the edge. This means the location estimate has high uncertainty in the along-edge direction — the feature can slide along the edge freely. Such points are useless for alignment since you can't pin them down spatially.
05 Orientation assignment

For each surviving keypoint at location (x, y) and scale σ, an orientation is assigned based on local image gradients. This is the step that makes SIFT rotation-invariant.

Gradient magnitude and orientation are computed at the keypoint's scale layer:

m(x,y) = √[(L(x+1,y)−L(x−1,y))² + (L(x,y+1)−L(x,y−1))²] θ(x,y) = atan2(L(x,y+1)−L(x,y−1), L(x+1,y)−L(x−1,y))

An orientation histogram with 36 bins (10° each) is accumulated over a neighborhood of radius ~3σ. Each gradient vote is weighted by its magnitude and by a Gaussian falloff (σ = 1.5 × keypoint σ) centered at the keypoint — so nearby gradients matter more.

The dominant peak in the histogram becomes the keypoint's canonical orientation. A parabola is fit to the three bins around the peak for sub-bin precision. Any other local peak exceeding 80% of the dominant peak generates an additional keypoint copy with that orientation — this handles corners and junctions where multiple orientations are present.

How rotation invariance works
All subsequent descriptor computation rotates the coordinate frame to align with this canonical orientation. So if the same physical patch appears at 0° in image A and 45° in image B, both produce descriptors in a frame aligned to their respective dominant gradient — the descriptors are identical.
06 SIFT keypoint descriptor

Once a keypoint has a location (x, y), scale σ, and orientation θ, the descriptor is computed from a 16×16 pixel neighborhood around the keypoint, rotated to the canonical orientation.

This patch is divided into a 4×4 grid of 4×4 cells. Within each cell, gradient orientations (relative to the canonical orientation) are binned into an 8-bin histogram, weighted by gradient magnitude and a Gaussian window.

Patch: 16×16 pixels rotated to canonical orientation Grid: 4×4 spatial cells, each 4×4 pixels Histograms: 8 orientation bins per cell Total: 4 × 4 × 8 = 128 values

The 128-element vector is L2 normalized, then any values exceeding 0.2 are clamped (this reduces the influence of nonlinear illumination effects from specular reflections etc.), then the vector is re-normalized.

Matching uses Euclidean distance between descriptors. Lowe's ratio test rejects ambiguous matches: a match is accepted only if:

d₁ / d₂ < 0.8 where d₁ = nearest neighbor distance d₂ = second nearest neighbor distance

A ratio close to 1 means two descriptors are nearly equally good matches — ambiguous and likely wrong. Ratios well below 1 indicate a clearly dominant match.

Why 4×4 × 8 and not something else?
Lowe empirically tested many configurations. Larger grids (e.g. 8×8) capture more spatial structure but become sensitive to geometric distortion. More orientation bins add discriminability but also noise. The 4×4×8 = 128 configuration hit the sweet spot between distinctiveness, compactness, and stability under realistic image transformations.
07 Comparison to other scale-invariant detectors

SIFT is not the only scale-invariant detector. Several alternatives trade different properties:

Method Detection Descriptor Speed Notes
SIFT DoG extrema 128-D gradient histograms Slow Most thoroughly validated; was patented until 2020, now public domain
SURF Hessian-based (box filters) 64-D Haar wavelet responses ~3× faster Uses integral images for fast approximations; less accurate than SIFT on large viewpoint changes
ORB FAST corners + Harris 256-bit binary (BRIEF variant) Very fast Real-time capable; binary descriptors matched with Hamming distance; less robust to scale changes
KAZE / AKAZE Nonlinear scale-space extrema M-LDB binary or float Moderate Scale-space built on nonlinear diffusion — better edge/boundary preservation than Gaussian blur
Harris-Laplace Harris corners at Laplace scale Varies (often SIFT-like) Moderate Detects corners specifically; scale selected at LoG extremum — good repeatability
SuperPoint Learned (CNN) 256-D learned descriptor GPU fast Self-supervised deep learning approach; outperforms SIFT in many benchmarks; requires GPU
SIFT in biomedical imaging specifically
Biomedical images often lack the rich texture that SIFT relies on (e.g. featureless tissue regions, repetitive cell patterns). Mutual information-based intensity methods are often preferred for mono-modal registration. SIFT is most useful in multi-modal or multi-stain scenarios where the image appearance changes significantly and intensity methods fail. Modified SIFT variants tuned for histology and fluorescence microscopy exist in the literature.

The key invariance properties to know for each:

  • SIFT / SURF: scale + rotation invariant, partial affine robustness
  • ORB: rotation invariant, not scale invariant without explicit pyramid handling
  • Harris (no scale): rotation invariant only — it was Harris's limitation that motivated scale-space extensions
  • Learned (SuperPoint etc.): implicitly learn whatever invariances are in the training data — can generalize beyond hand-engineered invariances
